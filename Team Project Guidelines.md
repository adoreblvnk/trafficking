# Timeline and deliverables for Team Project Part 2

You are expected to use the engine you built over the first 7 weeks of this module to create one of the following:

*   **Game:** It should have some engaging gameplay, designed aligned to a real-world expectations or requirements (See samples below)
*   **Simulation:** It should simulate something real world (see samples below)

The problem must be solved well, so the client (based on the selected problem and lab in charge approval) is happy and it would address the target audience’s needs.

Remember the focus for this project is on the **quality of the code** your product and your ability to take **reusable components** (your engine) to solve a separate problem (your game or simulation), so the complexity of the game or simulation is not the focus of your grade, find a way to keep these things interesting but simple while still demonstrating the capabilities of your engine and showcasing the quality of your code.

While developing your game or simulation, continue to:

*   Adhere to software design principles such as **SOLID**
*   Implement at least **three design patterns**
*   Ensure a clear separation between engine code (more abstract side of things / managers) and game/simulation code (more concrete side of things specific to your game/simulation), to demonstrate appropriate architecture.

Some suggestions for a game that would align to real-world expectation or requirement might include:

*   Getting kids interested in **Language Learning**
*   Educating families and parents about **Healthy Eating**
*   Getting families aware of and supporting **Sustainable Living**
*   **Your own idea to be discussed with your lab-in-charge**

Some suggestions for a simulation that may simulate something in the real world:

*   A rocket simulation
*   A crowd simulator
*   A traffic simulator
*   A physics sandbox (example: simple suspension simulation or solar system gravity simulation)
*   **Your own idea to be discussed with your lab-in-charge**

Continue to appropriately use classes, objects, inheritance, polymorphism and error handling.

Ensure your code is robust, reusable and most importantly scalable, for example, is it easy to add more players, more enemies, more levels, more menus (for a game), or is it easy to add more planets, more rockets, more cars (for the simulation examples above). Does your code have low coupling? Would it be easy to use classes and components you’ve created in other applications without needing to change much or import irrelevant classes?

The application of good object-oriented programming practices to solve a problem is the main focus here, the game design/simulation complexity won’t be graded apart from 1. You’ve come up with an interesting problem to solve and solved it and 2. how good it is at showcasing your engine and your mastery of using reusable code, writing good code, object-oriented programming, design patterns and good architecture design.
